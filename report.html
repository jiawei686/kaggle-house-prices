1. Task and data

Predict the sale price of houses in Ames, Iowa. The metric is RMSE between the log of the predictions and the log of the true prices, so every number in this report is in log space and directly comparable to the leaderboard.

SalePrice is right-skewed (skew 1.88); after log1p it is close to normal (0.12). 43 of the 79 columns are categorical, and many are missing on purpose — no basement, no garage, no pool — so missingness carries information.

2. Method

Step 1. Target transform

Fit on log1p(SalePrice), predict with expm1. This matches the metric and shrinks the long tail, so linear models and trees are compared on the same error scale.

Step 2. Features

27 engineered columns in four groups:

  • Semantic fill. 15 columns where NA means "none" (PoolQC, Alley, Fence, Bsmt*, Garage*) are filled with None and then encoded ordinally; 10 area columns are filled with 0. LotFrontage uses the median of its neighborhood.
  • Ordinal encoding. 23 quality columns are grades, not categories, so Ex > Gd > TA > Fa > Po becomes 0–5. This keeps the direction of "better" that one-hot throws away.
  • Aggregates. TotalSF, TotalBath (half baths weighted 0.5), TotalPorch, TotalRooms.
  • Interactions and ratios. QualSF, QualLivArea, BsmtScore, GarageScore, plus 6 ratios such as AvgRoomSF and SFperLot. These let the linear models express "large and high quality" as a product.

Result: 106 columns for trees (native categorical dtype), 252 for linear models after one-hot.

Step 3. Models

Six models from two families, so that blending has something to combine:

Each model ran in its own process with BLAS pinned to one thread; the machine had about 200 MB of free memory and multi-threaded BLAS was being killed by the OOM killer.

Step 4. Validation

One fixed split, KFold(10, shuffle=True, random_state=42), shared by all six models so the out-of-fold predictions line up for blending. Every tuned parameter (alpha, number of trees) is chosen inside the training fold only. Test predictions are the mean of the 10 fold models in log space.

Step 5. Blending

Weights come from non-negative least squares on the OOF matrix: min ||y - Σw·oof||₂ with w ≥ 0. The non-negativity constraint stops models from cancelling each other. To check whether the weights themselves overfit, I refit them on 9 folds and scored the held-out fold.

3. The Edwards outlier

The first submission scored 0.12165 while CV said 0.1059. A gap of 0.0157 is wider than the 0.008–0.012 this competition usually produces, so I looked for where it came from. Almost all of it was one test row.

Step 6. Find the row

Test Id 2550 was predicted at 800,000, clipped from something higher. The next highest prediction in the whole test set was 580,361. The row: OverallQual=10, GrLivArea=5,095, built 2008, in Edwards.

Step 7. Compare with training rows

Two training houses in Edwards are over 3,000 sqft, and both sold far below what their size suggests.

Edwards overall: 100 training rows, median 121,750, max 320,000. Id 2550 is the only test row with GrLivArea above 4,000.

Step 8. Why it happened

I had dropped the two rows where GrLivArea > 4000 and SalePrice < 300000, which is common practice and did improve CV from 0.1367 to 0.1100. The cost was that the training data no longer contained a single example of a large cheap house in Edwards. The model saw size and quality and extrapolated, which is exactly what a linear model does when the counter-example is gone.

The arithmetic checks out. With a true price near 170,000, the log error is log(800000/170000) = 1.55, and one row out of 1,459 contributes √(1.55²/1459) ≈ 0.041 to the RMSE — about the whole gap. Removing that single error from v1 leaves 0.1147, matching the 0.1157 measured on the corrected file.

Step 9. The fix

No hand-assigned values. I trained a second pair of trees (XGBoost and LightGBM, same settings as Table 2) on the data with the two outliers kept, and used them only for rows of this type. With the counter-examples present the tree can split on the interaction, and it returns 251,322 for Id 2550, in line with the other Edwards sales.

One row changed. The other 1,458 predictions are byte-identical to v1, so the validation results in Table 3 still apply.

5. What to take away

  • CV on this competition is optimistic by about 0.015. Two reasons. The fold training sets are smaller than the full training set, and dropping outliers helps CV twice (the row is removed and it is also never in the validation fold) while that benefit does not exist on the test set.
  • Error analysis beats another model. Blending six models gained 0.0041; finding one bad row gained 0.0060 in score and 687 places. The next hour was better spent reading residuals than adding estimators.
  • The leaderboard is partly contaminated. The top 77 entries score exactly 0.00000, which is a perfect match against the original Ames dataset rather than a model. Only about 110 teams beat 0.11.
  • No outside data. Matching test rows to the original Ames file would score near zero and is leakage, so it was not used. The Id 2550 correction comes only from training rows in the same neighborhood.
  • Blending has a ceiling here. The honest nested estimate beats equal weights by 0.0006. More models from the same families will not move the number.

6. Reproduce

git clone https://github.com/jiawei686/kaggle-house-prices && cd kaggle-house-prices

# Python 3.13, lightgbm 4.7.0, xgboost 3.4.1, catboost 1.2.10, scikit-learn 1.9.1
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1   # low-memory machine, single thread

kaggle competitions download -c house-prices-advanced-regression-techniques -p data/
cd data && unzip -o house-prices-advanced-regression-techniques.zip && cd ..
mkdir -p preds

for m in lasso ridge enet lgbm xgb cat; do python run_one.py $m; done  # per-model OOF
python blend.py             # NNLS blend -> submission_blend.csv   (v1, LB 0.12165)
python fix_outlier_test.py  # Edwards fix -> submission_v2.csv     (v2, LB 0.11569)
